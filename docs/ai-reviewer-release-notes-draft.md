## 新功能

- **大型 PR 处理**
  - 文件数超过 `max_files` 时，按优先级截断：代码优先，其次文档，最后是锁文件、快照、删除和纯改名；同档位变更行数多的在前。
  - 新增输入 `warn_files`（默认 50）：文件数超过时在摘要评论里提醒。
  - 新增输入 `initial_pr_summary_only`（默认 `true`）：新增文件至少 80 个、且占比超过 90% 的“初始化类 PR”，自动审查时只出摘要、不做行级审查，并把 HEAD 记为已审查。用户主动发 `@ai-reviewer review` / `full review` 时照常逐文件审查。
- **Analysis chain**：只读代码探查工具；web search 展示搜索词与来源域名。
- **审查质量**：模型输出严重级别标签（critical / major / minor / nit）；修复建议不会掩盖问题；提示词平台中性化。
- **GitLab 相关**（本次一并发布，验证另行进行）：流水线按触发原因与审查结果命名、日志按阶段折叠并省掉可省的 bot 写入、bot 凭据支持按项目映射、bot 账号更换后可认领旧账号的摘要与评论、私有化 GitLab 的产物发布流程。

## 行为变化（升级前请阅读）

| 变化                  | 你会看到什么                                                                                                      | 需要做什么                                                            |
| --------------------- | ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 缺少 `OPENAI_API_KEY` | 以前 job 显示成功（绿色）但其实没有审查；现在 **job 红色失败**，错误信息写明检查该 Secret                         | 确认 Secret 已配置且不为空。来自 fork 的 PR 拿不到 Secret，会因此失败 |
| 命令限流              | 同一用户 60 秒内最多发送 10 条命令，超出的收到“请求过于频繁”的提示；每条命令多一次读取评论的 API 调用             | 无需配置                                                              |
| `triage` 权限         | `triage` 角色现在可以执行 `@ai-reviewer configuration`（此前被误判为 read）                                       | 无需配置                                                              |
| shell 工具            | 开启 `enable_shell` 时，命令输出会脱敏，名字像密钥的环境变量（`*_TOKEN`、`*_KEY`、`*_SECRET` 等）不再下发给 shell | 无需配置                                                              |
| 提示词                | 仅格式化的改动（引号、分号、缩进、空格）判为无需审查；样式、命名、`any` 类问题最高为 minor                        | 无需配置；模型行为可能有波动                                          |
| 同一问题去重          | 同文件内，已有未解决评论报告过的同一问题（按评论里的代码标识符判断）不再重复发布                                  | 无需配置                                                              |

## 修复

- `triage` / `maintain` 角色被错误识别（旧的权限字段把 triage 折叠成 read）。
- shell 命令输出没有任何脱敏。
- 在 CI 里开启 Prettier 后永远报不出问题（输出带终端颜色码，解析不到）。
- 多个 lint 工具共用同一个安装目录：一个工具安装失败，会让另一个工具的可执行文件消失。现在每个工具独立目录。
- 用真实 bot 账号名（带 `[bot]` 后缀的 App）@ 时无法触发命令。
- 自动审查暂停后，没有新提交时发 `@ai-reviewer review` 会从 base 全量重审并重复发布评论。现在提示“HEAD 已审查”。
- 一次推送改动很多文件时，增量审查会静默漏审（`compare` 接口最多返回 300 个文件，取交集后丢掉了其余文件）。
- 增量审查起点现在与平台返回的提交顺序无关。
- 与当前文件任何 patch 都不重叠的评论不再硬挂到第一个 hunk，而是丢弃并在日志留痕。
- 严重级别标签解析：只读首行、白名单校验、合并前逐条取出。

## 已知限制

- 评论数达到 `max_review_comments` 上限时，被截断的问题没有持久化；之后的 `full review` 是否补发依赖模型重新给出，**不保证完整**。
- 对 401、400 这类不可重试的 OpenAI 错误也会按 `openai_retries` 重试（默认 5 次，退避累计约 31 秒），只是浪费时间，不影响结果。
- 请求带 web search 被 API 拒绝时，没有“去掉搜索再试一次”的回退，会按失败项处理，摘要里提示审查不完整。
